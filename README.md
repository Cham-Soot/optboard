# 옵션 행사가 누적표

KIS API의 KOSPI200 옵션 시세를 GitHub Actions로 수집하고 GitHub Pages에 표시합니다. 개인 마킹·메모는 Google 로그인 후 본인에게만 허용된 Firebase 저장소에 동기화합니다. 인터넷을 사용하는 개인용 도구입니다.

## 저장 위치

| 자료 | 저장 위치 | 접근 범위 |
|---|---|---|
| 시세·수집 상태 | `data/`, 공개 Pages | 누구나 |
| 시세 보관본 | `archive/` | 공개, 개인 메모 제외 |
| 마킹·메모·수정 전 이력 | Firestore `users/{본인 UID}/` | 규칙에 등록된 본인 계정 |
| 전송 대기 메모 | 해당 브라우저 저장소 | 해당 기기·브라우저 프로필 |
| 내려받은 메모 백업 | 개인이 선택한 폴더 | 파일을 가진 사람 |
| 기존 개인 자료·복구 사본 | `.private/`, `data/marks.json` | Git 제외 |

`#me`는 이전 방식의 기기 내 편집 모드입니다. 접근 권한은 이 표시가 아니라 Firestore 규칙에서 검사합니다. 공용 기기에서는 개인 Google 계정으로 로그인하지 않는 것이 좋습니다.

## 화면 사용

1. **개인 메모 로그인**에서 등록한 Google 계정을 선택합니다.
2. 메모를 입력하거나 고가·저가를 마킹하면 기기에 먼저 저장하고 서버에 전송합니다. 상단의 **동기화 완료 / 전송 대기 / 충돌** 표시를 확인합니다.
3. 다른 기기도 같은 계정으로 로그인하면 저장된 마킹·메모를 불러옵니다.
4. 두 기기가 같은 항목을 다르게 고쳤으면 **수정 충돌**에서 두 내용을 비교하고 유지할 내용을 선택합니다. 메모 1과 메모 2처럼 서로 다른 항목의 수정은 함께 반영합니다.
5. **메모 백업**에서 JSON 파일 저장, 기존 파일 불러오기, 최근 수정 전 내용 복원을 할 수 있습니다. 백업 파일은 GitHub에 올리지 않습니다.

고가 빨강·저가 파랑과 기존 네모/아랫줄 순환, 콜 고가 ↔ 풋 저가의 대각 연동 규칙을 유지합니다. 엑셀 내보내기는 현재 화면의 시세와 로그인한 본인의 메모를 포함한 개인 파일입니다.

## 최초 연결

현재 `optboard-memo`의 Google 로그인과 서울 지역 Firestore 연결을 완료했으며 `enabled: true`입니다. 지정한 본인 계정으로 사용합니다. 기존 개인 메모 129개 행을 가져와 원본과 일치함을 확인했습니다. 아래 절차는 새 프로젝트로 이전하거나 다시 구성할 때 참고합니다.

1. Firebase **Spark** 프로젝트를 만들고 결제 계정을 연결하지 않습니다. Google Analytics는 필수가 아닙니다.
2. 웹 앱을 등록하고 공개 웹 설정을 `assets/firebase-config.mjs`의 `firebase`에 넣습니다. 서비스 계정 비밀키는 사용하지 않습니다.
3. Authentication에서 Google 로그인을 활성화하고 Pages 호스트를 승인 도메인에 추가합니다. 로컬 검증 시 필요한 경우에만 `localhost`를 추가합니다.
4. Firestore Standard 데이터베이스를 **프로덕션 모드(기본 접근 차단)**로 만듭니다.
5. Google 로그인으로 생성된 본인의 UID를 확인하여 `ownerUid`와 `firestore.rules`의 지정값에 동일하게 넣습니다. 규칙의 본인 계정 검사와 기본 접근 차단을 유지한 채 배포합니다.
6. 본인 계정의 읽기·쓰기, 다른 계정과 비로그인 사용자의 접근 거절을 확인한 후 동기화를 사용합니다.
7. GitHub 저장소 Settings → Pages → Source를 **GitHub Actions**로 설정합니다. 기존 KIS Secrets는 그대로 사용합니다.

웹 설정의 API 키는 Firebase 앱을 식별하는 공개 설정이며 비밀 관리자 키가 아닙니다. 데이터 접근은 보안 규칙과 로그인으로 제한합니다. [Firebase 공식 안내](https://firebase.google.com/docs/projects/api-keys)

Spark 무료 한도 내에서 사용합니다. 결제 계정을 연결하지 않은 상태에서는 한도 초과 시 사용이 제한되며 유료 플랜으로 자동 전환되지 않습니다. 관리형 백업·PITR 등 유료 기능은 사용하지 않습니다. 이 앱의 수정 이력과 JSON 백업은 별도 기능입니다. [요금제](https://firebase.google.com/pricing), [Firestore 무료 한도](https://firebase.google.com/docs/firestore/quotas)

## 자동 수집과 배포

- 예약: 월~금 한국시간 16:12, 18:36. 예약 실행은 지연되거나 누락될 수 있습니다.
- 거래일 달력은 하루 한 번 새로 확인합니다.
- 종목마스터에서 코드를 얻고 **요청일의 KOSPI200 지수**로 행사가 범위를 정합니다. 현재 전광판 값을 과거 날짜에 붙이지 않습니다.
- 계약별 일별 응답의 날짜, 가격 형식, OHLC 관계를 검사합니다. 응답 없음·오류·거래량 0을 구분합니다.
- 일부 종목 실패 시 성공한 값과 실패 상태를 저장합니다. 누락된 값으로 기존 정상 값을 덮지 않습니다.
- 최근 7일 범위의 미완료 종목을 묶어서 재조회합니다. 만기 후 재조회 가능 여부는 보장하지 않으므로 수집 오류를 확인해야 합니다.
- 수집 결과는 화면 상단과 `data/collection_status.json`에 표시됩니다. 거래량 0으로 확인된 종목은 미거래이며 값이 없을 수 있습니다.
- 성공 데이터부터 Git에 보존한 뒤 공개 화면을 만듭니다. `_site/`의 허용된 파일만 Pages에 명시적으로 배포합니다.
- 연결 오류 등 재시도 가능한 실패만 최대 4회 새 실행을 요청합니다. 불완전 수집은 최종 작업 결과에서 실패로 표시합니다.
- 만기 안내는 화면 배너와 기존 GitHub 이슈 알림에서 확인합니다.

기존 시세 중 새 `collection` 확인 정보가 없는 구간은 종목별 완전성 검증 이전 자료입니다. 날짜가 있다는 이유만으로 모든 종목이 검증됐다고 보지 않습니다.

## 내 PC에서 실행

Windows PowerShell 예시입니다. `-X utf8`은 터미널 입출력을 위한 옵션이며 원본 CP949 종목마스터는 코드에서 CP949로 읽습니다.

```powershell
python -X utf8 scripts/master.py
python -X utf8 scripts/calendar_sync.py
python -X utf8 scripts/collect.py --expiry 202610 --date 2026-09-11
python -X utf8 scripts/build_viewer.py --site-dir _site
python -X utf8 scripts/verify_public.py
python -X utf8 -m http.server 8765 --bind 127.0.0.1 --directory _site
```

실제 사용 시 월물·날짜를 바꿉니다. Google 로그인을 쓰는 화면은 파일 더블클릭이 아니라 Pages 또는 로컬 HTTP 주소로 엽니다. KIS 키는 `.env` 또는 환경변수에만 둡니다.

| 종료코드 | 뜻 |
|---|---|
| 0 | 해당 범위 완료 또는 자동 실행일이 휴장 |
| 2 | 입력·설정·달력 확인 필요 |
| 3 | 네트워크 등 일시적 오류, 재시도 가능 |
| 4 | 누락·잘못된 응답 등 불완전 수집 |

## 복구

1. **기존 메모 옮기기:** 각 브라우저의 기존 백업을 먼저 저장합니다. 새 화면에서 본인 로그인 → 메모 백업 → 이전 메모 가져오기 또는 백업 파일 불러오기를 선택합니다. 같은 행은 가져온 값으로 바뀌므로 기기마다 내용이 다르면 비교 후 가져옵니다.
2. **잘못 수정한 메모:** 메모 백업 → 최근 수정 전 내용 보기에서 복원하거나 개인 JSON 백업을 불러옵니다. 복원도 새로운 수정으로 기록됩니다. 빈 값도 삭제 기록으로 백업됩니다.
3. **과거 시세 누락:** `python -X utf8 scripts/backfill.py --expiry 202610 --from 20260907 --to 20260911`처럼 구간을 지정합니다. 실제 역사적 지수 응답으로 거래일과 행사가 범위를 확인합니다.
4. **월물 전체 교체:** 같은 명령에 `--reset`을 추가하면 지정 구간이 모두 조회된 경우에만 월물 파일 전체를 교체합니다. 원본은 `.private/backfill/`에 백업됩니다. 실패하면 원본을 유지합니다. 이미 생성된 보관본을 다시 만들려면 확인 후 `archive.py --expiry YYMM --force`를 별도로 실행합니다.
5. **기존 공개 엑셀의 메모 분리:** `migrate_archive_privacy.py`는 원본 엑셀과 메모 JSON을 `.private/legacy-archive/`에 보존하고 공개 엑셀을 시세만으로 다시 만듭니다. Git의 과거 버전은 이 명령으로 바뀌지 않습니다.

개인 오프라인 HTML이 필요한 경우에만 `python -X utf8 scripts/build_viewer.py --private`를 실행합니다. 결과 `.private/내화면.html`은 메모를 포함하므로 공개하지 않습니다.

## 검증

```powershell
python -X utf8 -m unittest discover -s tests -p 'test_*.py'
node --test tests/*.test.mjs
python -X utf8 scripts/verify_public.py
```

자동 테스트는 날짜 불일치, 부분 실패, 재조회, 공개·개인 자료 분리, 백업·삭제 복원, 두 기기 수정 충돌 등을 확인합니다. 실제 본인 계정의 메모·마킹 저장과 다시 불러오기를 확인했습니다. 배포된 규칙의 접근 제어 10개 사례를 서버에서 검사했고, 실제 비로그인 읽기 요청은 HTTP 403으로 차단됐습니다. 서로 다른 실제 기기에서의 사용은 같은 계정으로 로그인하여 동기화 완료 표시와 내용을 확인합니다.
